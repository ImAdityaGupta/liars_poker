# 18-claim neural CFR+: clip on read with plain MSE

## Question

The cumulative conditional trainer usually averages sampled regret increments at exact repeated information sets and clips the result before fitting. A state visited once has its noisy target clipped before the network can generalise across states. Does fitting each **signed** target with plain masked MSE and clipping the prediction when it is read produce a better average policy?

This is a practical recipe comparison, not a factorial isolation of loss weighting and clipping. The new mode uses `regret_positive_weight=0`; the historical cumulative conditional run uses `0.5`. Exact average-policy exploitability is the primary outcome. Lower is better.

## Method

- **Game:** 18-claim `r4_s4_h2_hp2pt_ss`, seed 17.
- **Training:** from scratch on CPU, 4,096 root traversals per player per iteration, full traverser-action expansion, conditional sampled advantage, cumulative regret units. The prior network output is still clipped before it enters the next target. The new target is signed and ungrouped. Regret fitting uses 24 steps of batch 1,024 with a 512-by-512 network and plain legal-action-masked MSE. Strategy fitting uses 6 steps with a 256-by-256 network, a 2-million-row reservoir and linear iteration weighting.
- **Budget:** 330 measured training minutes, matching the first segment of the existing `conditional4096` curve. Eight CPU threads. Policy snapshots and rolling resumable checkpoint every 15 training minutes.
- **Evaluation:** port 8765's independent exact evaluator checks the saved average policies and plots exact exploitability against measured training minutes and CFR+ iteration. Evaluation time is excluded from the trainer budget.

The historical comparison uses the same game and nominal training settings, with `aggregate_then_clip` and positive-target weight 0.5. It ran earlier on the same VM under changing CPU load. The code revision and target mode also differ, so the curves do not isolate one variable perfectly. The purpose is to decide whether the new recipe deserves further attention.

The live control is under `artifacts/cfr_plus_18_cumulative_regret/main_20260929/clip_on_read4096/clip_on_read__seed_17` on the VM. [The launcher](../../scripts/start_cfr_plus_18_clip_on_read_cpu.sh) registers it in `extra_arms.json` without changing the original run manifest, and starts it in tmux session `cfr18_clip_on_read_cpu`. The trainer is [here](../../scripts/run_cfr_plus_18_target_order_cpu_overnight.py). Port 8765 shows its curve alongside the historical cumulative conditional run. The trainer saves an initial checkpoint, so a restart before the first 15-minute checkpoint can resume from iteration zero.

## What to look for

- A sustained lower exact average-policy exploitability at matched iterations suggests signed fitting helps learning, independent of CPU contention.
- A time-axis gain with similar iteration-axis results suggests throughput is the main benefit of avoiding grouping.
- A late rise after an early gain would leave the plateau problem unresolved.
- One seed and non-contemporaneous training limit the strength of any small difference. A large and persistent difference would motivate a matched follow-up.
